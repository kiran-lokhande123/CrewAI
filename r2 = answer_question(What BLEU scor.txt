# Router - Retriever RAG Project

This project builds a two-agent RAG (Retrieval-Augmented Generation) system using CrewAI.

CrewAI is a Python library that provides the necessary tools and does important coordination work for building **Agents** and **RAG** systems. CrewAI acts like an orchestration layer, which coordinates calls to LLMs, tools, and so on.

It is instrumental in connecting two or more agents. Multiple agents are useful when a task can be divided into different roles. Each agent focuses on one job, which makes the system more reliable and easier to check and fix.

---

## Agents

The following two agents are built in the project:

* Router Agent: When a query is sent by the user, this agent directs the **Retriever** agent to the correct source of information. In this project, the information can be found in the PDF, on the Web, or it can be answered using the AI model's (LLM) own general knowledge. The Router itself does not search or answer the question.
* Retriever Agent: This agent acts based on the decision taken by the Router agent. For example, if the Router agent directs to the PDF document, the Retriever Agent searches for answers only in the PDF. This saves the Retriever agent time looking somewhere else.

## Knowledge Sources

The following routes are used for the following searches:

* PDF Search: `pdf_search`. This tool comes from CrewAI (crewai-tools).
* Web Search: `web_search`. This tool is provided by Tavily.
* LLM General Knowledge: `direct_llm`. No tool is used; the LLM answers directly.

## Setup and installation

This section helps us to configure the following keys:

* OpenAI API key: Use this key to connect to the LLM. This key is also required to search the PDF document, and to answer questions based on general knowledge that need no retrieval.
* Tavily API key: Use this key to search the web if the Router directs the query to web search.

The tools we are using here are the PDF search tool (CrewAI) and the web search tool (Tavily). These two tools are used only by the Retriever.

## How it works (example)

Question 2: "What BLEU score did the Transformer (big) model achieve?"

1. The question typed by the user is received by CrewAI.

2. The question is then forwarded to the Router Agent.

3. The Router, with the help of the LLM (AI model), decides where the answer can be found: in the attached PDF, on the web, or from the AI model's own general knowledge. In this case, the answer is in the PDF. The Router writes down its decision in a fixed format: where to look, why, and what to search for. Please note that the Router itself does not answer the question and does not search anything. Based on the Router's decision, the Retriever Agent is given only the matching tool.

4. The decision is passed to the Retriever Agent to act on it. The Retriever is allowed to search only the PDF, so it cannot look in the wrong place.
5. The Retriever, with the help of the LLM, uses the tool to search for the answer in the PDF. The LLM decides what to search for, and the PDF search tool provided by CrewAI returns the most relevant parts of the paper.
6. The searched result is refined by the LLM and passed again to the Retriever. The LLM writes the answer only from the retrieved text and adds the source (the section from which the answer is taken, 6.1).
7. The Retriever passes the final answer to CrewAI, which is then sent to the user. Every step is recorded in the trace logs.

## Challenges faced and trade-offs made

%pip install -q crewai crewai-tools langchain-community tavily-python python-dotenv

Here we used the second command as the **-U** universally forces newest version, even if they're already installed. This was creating conflict as pandas with lower were already installed.
Uisng **-q** removed the requirement of isntalling pandas of new versions and avoided conflict
